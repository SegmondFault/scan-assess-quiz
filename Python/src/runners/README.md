## Making Modules with the Python Runner

Modules are Python directories that contain a `runner.py` file with a `Runner` class that inherits from `BaseRunner`. The `Runner` class must implement the `run` method, which is where the logic for generating questions and answers will be implemented.
Example modules can be found in the `modules` folder, and are structured as such:

```python
class Runner(BaseRunner):

    def run(self, output_dir: Path, module_dir: Path) -> tuple[bool, list[Path]]:
        ...
```

The input parameters are:
- `output_dir`: a `Path` object pointing to the directory where the generated questions should be saved.
- `module_dir`: a `Path` object pointing to the directory of the module itself, which can be used to access any additional files or resources needed for question generation.

The `run` method should return a tuple containing:
- A boolean indicating whether the module ran successfully or not.
- A list of `Path` objects pointing to the generated question files in the `output_dir`.

The questions generated by the module should be saved in the `output_dir` as JSON files, following a specific structure that includes the question text, possible answers, and the correct answer. This structure will be used by the web app to display the questions and evaluate user responses. Questions can be generated statically or dynamically based on the results of scans or other operations performed within the `run` method.

The generated JSON files must follow the following structure:

```json
[
  {
    "q_id": 1,
    "tree_id": 2,
    "label": "Is there a clear person responsible for IT and security in your organization?",
    "answers": [
      {
        "a_id": 1,
        "label": "Yes, there is a clear person responsible",
        "score": {
          "third_party_management": "+10"
        },
        "recommendations": "",
        "follow_up_question_id": 2
      },
      {
        "a_id": 2,
        "label": "No, everyone fixes their own problems",
        "score": {
          "employee_management": "0",
          "logical_access": "0",
          "awareness_and_compliance": "0",
          "information_system": "-5",
          "local_area_network": "0",
          "third_party_management": "-5"
        },
        "recommendations": "",
        "follow_up_question_id": 2
      }
    ]
  },
  ...
]
```

Each question is represented as a JSON object with the following fields:
- `q_id`: A unique identifier for the question within the tree.
- `tree_id`: The identifier of the tree to which the question belongs. This number must be unique to the module unless the module is generating questions for an existing tree, in which case it should use the same `tree_id` as the existing questions.
- `label`: The text of the question to be displayed to the user.
- `answers`: A list of possible answers to the question, where each answer is represented as a JSON object with the following fields:
  - `a_id`: A unique identifier for the answer within the question.
  - `label`: The text of the answer to be displayed to the user.
  - `score`: A dictionary mapping category names to score values, which will be used to calculate the user's score in each category based on their selected answers. Not every answer needs to have a score for every category, but at least one answer per question should have a non-zero score for each category to ensure that the quiz can effectively evaluate the user's security posture across all categories.
  - `recommendations`: An optional string containing any recommendations or feedback to be provided to the user if they select this answer.
  - `follow_up_question_id`: An optional integer indicating the `q_id` of a follow-up question within the tree that should be presented to the user if they select this answer. If this field is not provided, the quiz will proceed to the next tree, starting at the lowest `q_id`.
